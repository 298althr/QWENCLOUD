ALTHR Autopilot - RAM Fix and Dashboard Enhancement Report

Date: July 15, 2026 | ECS: 47.84.106.210 | Branch: track4

1. Problem

The dashboard showed RAM at 93-96% (Critical) constantly. This was a false alarm. The monitoring code used mem.used / mem.total to calculate RAM usage. On Linux, mem.used includes buff/cache (disk cache that can be reclaimed instantly). The actual available memory was around 1000 MB but the system reported 1600+ MB as "used".

2. Root Cause

Two locations in the backend calculated RAM the same wrong way:

  • backend/src/monitors/monitor.js line 183 - used by the WebSocket metrics stream
  • backend/src/qwen/toolExecutor.js line 163 - used by the /api/health/server endpoint

Both used: ram = (mem.used / mem.total) * 100

Linux free -m output from the ECS confirmed the issue:

               total        used        free      shared  buff/cache   available
Mem:            1710         712         109          16        1095         997

The system had 997 MB available but reported 93%+ used because 1095 MB of buff/cache was counted as "used".

3. Fix Applied

Changed both locations to use mem.available instead of mem.used:

const used = mem.total - (mem.available || mem.free);
ram = (used / mem.total) * 100

This gives the actual memory pressure excluding reclaimable cache. The fix also adds ram_available_mb and ram_buff_cache_mb to the metrics output for transparency.

6. PWA Build Hang Fix

The Next.js PWA plugin (@ducanh2912/next-pwa) was hanging during service worker generation on the 1.7 GB ECS instance, consuming all available memory and freezing the instance.

Fix: Added DISABLE_PWA=true environment variable in the frontend Dockerfile. The PWA plugin checks this and skips service worker generation. The web app works normally without offline capabilities, which are not needed for the hackathon demo.

8. Docker Compose v1 Bug Fix

The ECS had docker-compose v1.29.2 (Python-based) which throws KeyError: 'ContainerConfig' when recreating containers with newer Docker engine versions. Fixed by installing docker compose v2.30.0 (Go-based) as a Docker CLI plugin at /usr/libexec/docker/cli-plugins/docker-compose.
